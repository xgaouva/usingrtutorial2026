(Reference) Importing SPSS Data

For those switching from SPSS to R, a first step is importing your SPSS data.

SPSS data files have a complicated setup with variable labels and value labels.R data frames or tibbles do not have such labels.

Here are two options for importing SPSS data.

Option 1. Export from SPSS to .csv and import .csv in R.

  • Export data from SPSS to a CSV file with value labels for categorical variables:
    • File > Export > CSV Data with Save value labels where defined instead of data values.
  • Use read_csv() (as you learned before) to import the CSV file.

Import the SPSS file data/glbwarm.csv and have a look at it.

Option 2. Import SPSS .sav file directly with tidyverse package haven.

The tidyverse package haven contains function read_sav() (or read_spss()) for importing SPSS (and other software packages) data files.

Import the SPSS file data/glbwarm.sav and have a look at it.

# The SPSS system file is available in the data directory of this tutorial.
glbwarm_spss <- haven::read_sav("data/glbwarm.sav")
# Inspect the variables.
str(glbwarm_spss)

Imported categorical variables such as ideology:

  • Are numerical codes with labels.
  • So, R treats these variables as numerical.
  • If you don’t want that, change them into factors.

Use the haven::as_factor() function to add a variable named sex_fct to tibble glbwarm_spss.

# Add sex as a factor to the tibble.
glbwarm_spss <- glbwarm_spss |> 
  mutate(sex_fct = haven::as_factor(sex))
# Inspect the original and new variable.
glbwarm_spss |> count(sex, sex_fct)

Passing the entire tibble glbwarm_spss to haven::as_factor()will change all labelled variables into factors.

I am not sure this is what you want here. Perhaps you would like to use the ideology variable as a seven-point scale.

Keep Learning & Teaching

If someone asks you: “Do you know R?”, you can now proudly and confidently say: “Yes, some of it.”

  • The R universe is large and versatile. Whatever data-related task you can come up with - there is likely going to be an R-based solution to your issues.

  • New projects will likely require you to learn new things in R.

  • Your collaborators are not R users? You can still use R to produce reproducible reports of your work for them that can be commented on and edited in a familiar program like Word. For curious collaborators, share resources (e.g., “Help, my collaborator is using R”).

  • Luckily there are lots of resources to help you develop yourself as an R programmer.

AI

  • AI tools are making coding easier and more convenient by the minute.
  • For instance, several AI tools can generate code based on prompts directly inside RStudio.
  • It is worth taking some time to consider the ethical implications of using AI in your work (e.g. https://www.unesco.org/en/artificial-intelligence/recommendation-ethics)

Don’t make the mistake to become a passive user. AI is only as good as the prompts you supply and it is not without its limitations. You’ll need at least a basic understanding of what you are doing in R AND with the AI to accurately describe what you want and understand when the AI is making a mistake or misinterpreting your prompts.

Always double-check and test any results!

Collaborate

There are various tools available to help you organize collaborations in R (e.g. when multiple people have to work on the same script or Quarto file). One approach is using GitHub.

  • Easy synchronization across all collaborators.

  • Secure version control features that also let you recover old versions.

  • Easily keep track of remaining issues and bugs.

###

Here is a simple workflow (although GitHub has many more great functionalities!):

  • Download GitHub Desktop: https://github.com/apps/desktop

  • Create a new repository which will hold all your files:

    • In the upper left corner, click “Add” and then “Create new Repository…”

    • Choose a name for your repository and choose the folder on your computer that contains the relevant files (e.g. the R Project, Quarto and data files).

    • Click on “Create Repository” and then “Publish repository”.

    • Private? If you want the repository to only be visible to collaborators, make sure “Keep this code private” is checked. Then hit “Publish Repository again.

  • Go to www.github.com and sign in to your account. You should now be able to see your newly created repository.

  • Under Settings > Collaborators you can add your collaborators to the repository.

  • Add an existing repository to GitHub Desktop:

    • In the upper left corner, click “Add” and then “Clone Repository…”

    • You will be asked to choose from a list of repositories you are able to access. Choose the repository you want to clone and a local path in which it should live on your computer. Then hit “Clone”.

    • GitHub will create a local copy of the repository on your computer that is linked to the online version.

  • Work collaboratively on a repository:

    • Fetch: First, make sure you are working with the latest version: Before you work on the repository, always click “Fetch origin”. Github Desktop will synchronize your computer with any changes your collaborators might have made to the online version of the repository.

    • Work: Make any changes files in the local path that belong to your repository. GitHub Desktop will automatically keep track of all the changes you made in the local path.

    • Commit & Push:

      • Once you are ready, go back to your repository on GitHub Desktop and give a short summary of the changes you’ve made in the lower left corner. Then hit “Commit”.

      • To actually synchronize your changes with the online repository, you then also need to hit “Push Origin” at the top of the GitHub Desktop window. The next time a collaborator fetches from the online repository, it will contain the changes you’ve made.

APA format article with apaquarto::

Instead of adapting a standard Quarto document, you can use apaquarto, which contains an APA7 article template.

A great extension for Open Science projects!

  • Write fully reproducible papers in Quarto and produce perfect, APA styled rendered documents in PDF or Word.
  • Include graphs and tables, designed according to APA style.
  • apaquarto integrates smoothly with .bib files and reference managers like Zotero.

Install apaquarto

  • Go to: https://github.com/wjschne/apaquarto

  • Click on Code (1) and then Download Zip (2)

  • Unzip the downloaded folder on your computer (remember the location).

  • Open the apaquarto.Rproj file inside the folder.

  • In RStudio, you can now open the template file template.qmd . It includes examples of various scenarios you might want to implement (e.g. citations, plots and tables).

  • Create a copy of the template.qmd file.
  • Inspect the contents of the template, check out the options.
  • Render it to pdf or Word and inspect the knitted document.
  • Apply your skills for cross-referencing sections, tables, and figures.

All information about apaquarto is available at https://github.com/wjschne/apaquarto .

Shiny

The shiny package is the RStudio contribution to interactive R products. Actually, this tutorial is made with Shiny and it contains a Shiny app, namely, the animated plots used in the Evaluating a plot Section.

Here is the code for these plots. You cannot run the code here because we cannot start a Shiny app from within a Shiny app (this tutorial). If you create a new Shiny app in RStudio (File > New File > Shiny Web App) and copy and paste the below code into the Shiny app file (replacing all existing contents), you can run the app from RStudio (use the Run App button).

Experiment with the user interface and the R code.

# load the shiny package
library(shiny)

# first part of the app: the User Interface (ui)
ui <- fluidPage(
    fluidRow( #the first (and only) row in the interface
        column(2, #the first (left) column, width 2 out of 12
               radioButtons("radio", label = h3("Select a plot"),
                            choices = list("Plot 1" = 1, #label and value if selected
                                           "Plot 2" = 2, 
                                           "Plot 3" = 3, 
                                           "Plot 4" = 4, 
                                           "Plot 5" = 5, 
                                           "Plot 6" = 6), 
                            selected = 1),
               #only a slider can be animated
               sliderInput("slider", label = "", min = 0, max = 20, value = 0,
                           step = 1, ticks = FALSE, 
                           animate = TRUE
               )
        ),
        column(10, #the second (right) column, width 10 out of 12
               plotOutput("regPlot") #containing the plot named regPlot
        )
    )  
)

# second part of the app: the R code
server <- function(input, output, session) {
  # create a plot named regPlot to be shown in the output
  output$regPlot <- renderPlot({
    # the basic (empty) plot  
    g <- ggplot(
      data = consumers,
      aes(x = ad_expo, y = brand_aw)
      ) +
      scale_x_continuous(name = "Exposure", breaks = 1:10, limits = c(1, 10)) +
      scale_y_continuous(name = "Brand awareness", breaks = 1:10, limits = c(1, 10)) +
      theme_bw( base_size = 14 )
    
    ## Create a plot version for each radio option
    if (input$radio == 1) { 
      # just add regression line and confidence interval to the empty plot
      g <- g + geom_smooth(method = "lm", 
                           formula = y ~ x, se = TRUE, 
                           color = "black")
    }
    else if (input$radio == 2) {
      # point size reflects brand_aw
      g <- g + 
        geom_point(aes(size = brand_aw), color = "grey") +
        geom_smooth(method = "lm", formula = y ~ x, se = FALSE)
    }
    else if (input$radio == 3) {
      # outlier not visible (and regression line without outlier)
      g <- g + 
        geom_point(size = 2, color = "grey") +
        geom_smooth(data = consumers[consumers$ad_expo > 1,], 
                    mapping = aes(x = ad_expo, y = brand_aw),
                    method = "lm", formula = y ~ x, se = FALSE) +
        scale_x_continuous(limits = c(4, 10))
    }
    else if (input$radio == 4) {
      # grey total regression line, red regression line without outlier
      g <- g + 
        geom_point(size = 2, 
          aes(color = ifelse(ad_expo > 1, "grey", "red")), show.legend = FALSE) +
        geom_smooth(method = "lm", formula = y ~ x, se = FALSE, 
                    color = "grey", size = 2) +
        geom_smooth(
          # trick: base R to create a subset of all consumers, omitting the outlier
          data = consumers[consumers$ad_expo > 1,], 
          mapping = aes(x = ad_expo, y = brand_aw),
          method = "lm", formula = y ~ x, se = FALSE, color = "red"
        ) +
        geom_text(x = 3.9, y = 4.3, label = "without outlier", 
                  size = 3, color = "red", alpha = 0.6) +
        scale_color_manual(values = c("red", "grey"))
    }
    else if (input$radio == 5) {
      # regression line per gender, with additional regression line 
      # for males without outlier
      g <- g + 
        geom_point(aes(color = gender), size = 2) +
        geom_smooth(
          method = "lm", formula = y ~ x, se = FALSE, aes(color = gender)
          ) +
        geom_smooth(
          data = consumers[consumers$ad_expo > 1 & consumers$gender == "male",], 
          mapping = aes(x = ad_expo, y = brand_aw),
          method = "lm", formula = y ~ x, se = FALSE, 
          color = "blue", linetype = "dashed"
        ) +
        geom_text(x = 4.1, y = 3.4, label = "without outlier", 
                  size = 3, color = "blue", alpha = 0.6)
    }
    else if (input$radio == 6) {
      # density conours and regression lines per gender
      g <- g + 
        geom_density2d(aes(color = gender),  adjust = 2) +
        geom_smooth(
          method = "lm", formula = y ~ x, se = FALSE, aes(color = gender)
          )
    }
    
    # Show plot, depending on slider value
    # This is the animation trick: slider values range from 0 to 20,
    # if it is 0, a text is shown, if it is 1 or 2 or at least 10, 
    # the plot is shown, a text is shown between 2 and 10, and
    # a text is added to the plot if the slider is 20.
    if (input$slider == 0) {
      #show press button text
      ggplot(data = consumers) + 
        geom_text(
          x = 0.5, y = 0.5, 
          label = "Press the little play button", size = 12
          ) 
    } 
    else if ((input$slider > 0 & input$slider < 4) | (input$slider > 10)) {
      # ask user to reset the slider 
      if (input$slider == 20) {
        if (input$radio == 3 ) {hor_pos = 7}
        else {hor_pos = 5.5}
        g <- g + geom_text(
          x = hor_pos, y = 8.5, 
          label = "Reset the slider to 0\nbefore you watch another plot.", 
          size = 8
          )
      }
      #show plot
      g
    } 
    else {
      # What did you see?
      ggplot(data = consumers) + 
        geom_text(
          x = 0.5, y = 0.5, 
          label = "What did you see?", size = 18
          )
    }
  })  
}

# the command to create and run the app
shinyApp(ui, server)
